  1. Critical Missing Functionality
   * Message History Retrieval: Currently, there is a route to send messages, but no route to fetch them. The only way to see a message right now is through the "latest message" preview in the
     conversation list or via a real-time WebSocket event.
   * Read Status / Marking as Read: While the database has a last_read_at column, there is no endpoint to update it. This means you can't mark a conversation as "read," and the unreadCount will
     never decrease.
   * Testing Suite: There are zero tests (unit, integration, or E2E) in the project. For a real-time application, automated tests are crucial to ensure that WebSocket events and race conditions are
     handled correctly.

  2. High-Priority Chat Features
   * Presence (Online/Offline Status): The server tracks active WebSocket connections internally, but this status isn't broadcasted. Users can't see who is currently online or when they were "Last
     Seen."
   * Typing Indicators: There is no logic for "User is typing..." events, which are standard in modern chat apps.
   * Pagination: The conversationListService fetches all conversations at once. As a user's history grows, you'll need cursor-based pagination for both conversations and message history.
   * User Profile Management: There is no "Update Profile" endpoint to change a user's name or set their imageUrl.

  3. Polish & Advanced Features
   * Media & File Attachments: Messages are currently restricted to plain text. There's no support for sending images, videos, or documents.
   * Message Reactions & Replies: The data model doesn't support emoji reactions or message threading (replies).
   * Search: There is no functionality to search for specific messages or to find new users to chat with (beyond knowing their exact ID).
   * Push Notifications: To keep users engaged when the app is closed, you'll need integration with a service like FCM (Firebase Cloud Messaging) or Web Push.
   * Soft Deletes UI: You have isDeleted in the schema, but no logic to handle how a "This message was deleted" placeholder should look in the API response for other users.

  4. Technical Debt & Infrastructure
   * API Documentation: There is no Swagger or OpenAPI specification to help frontend developers integrate with the API.
   * Rate Limiting: The API is currently open to abuse (e.g., spamming the sendMessage endpoint).
   * Logout/Session Revocation: The app uses JWT, but there's no mechanism to "logout" (revoke a token) or handle refresh tokens.
